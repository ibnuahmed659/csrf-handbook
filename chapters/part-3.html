QAYBTA III

QAYBTA III ANATOMY OF CSRF

  • 18 qaybood
  • 8 tusaale

CSRF waa nooc gaar ah oo attack ah. Wuxuu leeyahay shuruudo gaar ah. Wuxuu leeyahay dabeecad gaar ah. Wuxuu leeyahay falsafad gaar ah.

Shuruudaha CSRF: Afarta Tiir

CSRF wuxuu dhacaa kaliya haddii afartan shuruudood ay buuxaan. Haddii mid ka mid ah aanu buuxin, CSRF ma dhaco. Waa afarta tiir ee CSRF.

Tiirka 1: Action-ka Waa In Uu Beddelaa State

Waa in uu jiro action oo wax beddela. Action-ka waa in aanu ahaan read-only. Waa in uu ahaadaa state-changing.

Tusaale:

  • POST /change-email — Haa, wuxuu beddelaa state.
  • POST /change-password — Haa, wuxuu beddelaa state.
  • POST /transfer — Haa, wuxuu beddelaa state.
  • GET /profile — Maya, waa read-only.
  • GET /search — Maya, waa read-only.

Action-ka waa ujeedda. Waa waxa attacker-ku rabo. Haddii action-ku aanu beddelin state, attacker-ku kama faa'iidaysto. Wuxuu rabaa impact. Wuxuu rabaa side effect. Wuxuu rabaa wax beddela.

Haddii action-ku beddelo state aan muhiim ahayn (tusaale "change theme"), CSRF wuu jiraa laakiin impact wuu yar yahay.

Tiirka 2: Authentication Waa Cookie-Based

Authentication-ka waa in uu cookie-based yahay. Waa in uu browser-ku si toos ah u diraa cookie-ga.

Tusaale:

  • Session cookie — Haa, waa cookie-based.
  • JWT cookie — Haa, waa cookie-based.
  • JWT header (Authorization: Bearer ...) — Maya, attacker-ku ma maamulo.
  • API key header — Maya, attacker-ku ma maamulo.
  • Basic auth — Haa, browser-ku wuu diraa.

Authentication-ka waa badge. Waa possession. Waa wax browser-ku hayo. Haddii authentication-ku aanu cookie-based ahayn (tusaale header-based), attacker-ku ma maamulo. CSRF ma dhaco.

CSRF wuxuu ku xiran yahay browser-ku si toos ah u diraa cookie-ga. Haddii authentication-ku uu ku jiro header oo attacker-ku maamulo, waa XSS ama token theft, ma aha CSRF.

Tiirka 3: Ma Jiro Token Sir Ah (Ama Waa La Jabin Karaa)

Macnaha Waa in aanu jirin token sir ah oo attacker-ku aanu garanayn. Ama haddii uu jiro, waa in la jabin karo.

Tusaale:

  • Ma jiro token — Haa, CSRF wuu dhacaa.
  • Token wuu jiraa laakiin lama xaqiijin — Haa, CSRF wuu dhacaa.
  • Token wuu jiraa laakiin lagu xaqiijiyay method gaar ah — Haa, CSRF wuu dhacaa (method override).
  • Token wuu jiraa laakiin lagu xaqiijiyay presence — Haa, CSRF wuu dhacaa (tirtir token).
  • Token wuu jiraa laakiin lagu xaqiijiyay cookie — Haa, CSRF wuu dhacaa (CRLF injection).
  • Token wuu jiraa oo si sax ah loo xaqiijiyay — Maya, CSRF ma dhaco.

Token-ku waa caqabad. Waa obstacle. Waa defense. Haddii token-ku maqan yahay ama la jabsan karo, attacker-ku wuu ka gudbaa. Haddii token-ku adag yahay, attacker-ku ma gudbi karo.

Token-ku waa in uu sir yahay. Waa in uu random yahay. Waa in uu session-ka ku xiran yahay. Waa in uu single-use yahay. Haddii mid ka mid ah aanu buuxin, waa la jabsan karaa.

Tiirka 4: Browser-ku Wuxuu Diri Karaa Request-ka

Waa in browser-ku uu diri karo request-ka cross-site. Waa in aanu jirin caqabad oo browser-ku joojinayo.

Tusaale:

  • SameSite=None — Haa, browser-ku wuu diraa.
  • SameSite=Lax + POST — Maya, browser-ku ma diro.
  • SameSite=Lax + GET + top-level — Haa, browser-ku wuu diraa.
  • SameSite=Strict — Maya, browser-ku ma diro.
  • CORS preflight — Maya, browser-ku ma diro (haddii aan la ogolaan).
  • CORS misconfiguration — Haa, browser-ku wuu diraa.

Browser-ku waa gatekeeper. Waa guard. Haddii browser-ku uu diido, attacker-ku ma gudbi karo. Haddii browser-ku uu ogolaado, attacker-ku wuu gudbaa.

Browser-ku wuxuu leeyahay rules oo ku saabsan cross-site requests. SameSite waa rule. CORS waa rule. SOP waa rule.

Noocyada CSRF

CSRF wuxuu leeyahay noocyo badan. Nooc kastaa wuxuu leeyahay dabeecad iyo farsamo gaar ah.

GET-Based CSRF

Request-ku waa GET. Action-ka wuxuu ku jiraa query string.

Tusaale:

GET-based CSRF waa nooca ugu fudud. Waa nooca ugu horeeya. Wuu shaqeeyaa sababtoo ah browser-ku wuxuu si toos ah u soo raraa images. Attacker-ku ma u baahna form.

GET-based CSRF waa mid naadir ah maalmahan. Developers-ku waxay barteen in aanay isticmaalin GET for state-changing actions. Laakiin wali wuu jiraa — haddii developer-ku uu isticmaalo $_GET['email'] si uu u beddelo email, GET-based CSRF wuu shaqeynaa.

Marka aad aragto GET /change-email?email=..., is weydii: "muxuu server-ku u ogolaaday GET inuu beddelo state?" Tani waa red flag.

POST-Based CSRF

Request-ku waa POST. Action-ka wuxuu ku jiraa body.

Tusaale:

POST-based CSRF waa nooca ugu badan. sababtoo ah browser-ku wuxuu si toos ah u submit-gareeyaa forms. Attacker-ku wuxuu isticmaalaa document.forms[0].submit().

Marka aad aragto POST /change-email, is weydii: "Ma jiraa CSRF token?" Haddii uumaqan, waa red flag.

WebSocket CSRF (CSWSH)

Request-ku waa WebSocket handshake. Waa GET laakiin wuxuu leeyahay Upgrade: websocket.

Tusaale:

CSWSH waa nooc gaar ah. Waa CSRF nooca WebSocket.

CSWSH wuxuu u baahan yahay WebSocket connection. Waa in la furo connection. Waa in la diraa messages. Waa in la exfiltrate-gareeyaa xogta.

Marka aad aragto WebSocket handshake, hadii uu maqan yahaya CSRF token?" waa red flag.

JSON-Based CSRF

Request-ku wuxuu dirayaa JSON. Wuu adag yahay sababtoo ah Content-Type: application/json wuxuu kiciyaa preflight request.

Tusaale:

JSON-based CSRF waa nooc adag. Oo cusub. haddii server-ku uu aqbalo text/plain ama application/x-www-form-urlencoded. Wuxuu isticmaalaa enctype="text/plain" si uu u sameeyo JSON-like body.

JSON-based CSRF wuxuu u baahan yahay server-ku inuu aqbalo content-type kale. Haddii server-ku uu diido text/plain, JSON-based CSRF ma shaqeeyo.

Marka aad aragto API endpoint oo JSON ah, is weydii: "Ma aqbalaa text/plain?" Haddii ay haa tahay, waa red flag.

Clickjacking + CSRF

Dabeecadda: Attacker-ku wuxuu isticmaalaa iframe si uu victim ugu qasbo inuu riixo button. Waa CSRF oo nooc kale.

Tusaale:

Clickjacking Waa visual CSRF. browser-ku wuxuu u ogolaadaa iframe. Wuxuu isticmaalaa transparency iyo positioning.

Clickjacking wuxuu u baahan yahay X-Frame-Options maqan. Haddii X-Frame-Options jiro, clickjacking ma shaqeeyo.

Sida Loo Helo CSRF

CSRF ma aha wax lagu helo shil. Waa wax lagu helo hab. Waa wax lagu helo fikir. Waa wax lagu helo systematic approach.

Tallaabo 1: Hel Dhammaan Actions-ka State-Changing

Waa in la helo dhammaan actions-ka beddela state. Ma aha mid. Ma aha laba. Waa dhammaan.

  • Burp Spider — wuxuu helaa links.
  • ffuf/gobuster — wuxuu helaa endpoints.
  • JavaScript analysis — wuxuu helaa endpoints qarsoon.
  • API documentation — wuxuu helaa endpoints.
  • Sitemap.xml, robots.txt — wuxuu helaa paths.

Waa in la helo dhammaan actions-ka. Waa in la sameeyaa inventory.

Tallaabo 2: Falanqee Request-ka: Waa in la falanqeeyaa request-ka. Waa in la ogaado qayb kasta.

Farsamo:

  • Method — GET, POST, PUT, DELETE?
  • Cookies — session, csrf, csrfKey?
  • Body — csrf token, parameters?
  • Headers — Origin, Referer, Content-Type?

Tallaabo 3: Tijaabi Defenses

Waa in la tijaabiyaa defenses-ka. Waa in la ogaado waxa jira iyo waxa maqan.

Farsamo:

  • Ma jiraa CSRF token?
  • SameSite maxay tahay?
  • Ma jiraa Referer/Origin validation?
  • Ma jiraa custom header?

Waa in la tijaabiyaa mid kasta. Waa in la diiwaangeliyo natiijada.

Tallaabo 4: Isku Day Bypass

Waa in la isku dayaa bypass. Waa in la jabiyaa defenses-ka.

Farsamo:

  • Tirtir token.
  • Beddel method.
  • Beddel token user A → user B.
  • CRLF injection.
  • Client-side redirect.
  • Sibling domain + XSS.
  • Cookie refresh.

Fikirka Developer-ka: Sida Looga Hortago CSRF

Developer-ku wuxuu u baahan yahay inuu fahmo saddex waxyaabood:

1. CSRF token waa in uu session-ka ku xiran yahay.

2. SameSite waa in la dhigo.

3. Origin/Referer waa in la xaqiijiyaa (si sax ah).

Developer-ku wuxuu u baahan yahay inuu fahmo falsafadda CSRF. Wuxuu u baahan yahay inuu ogaado in browser-ku uu confused deputy yahay. Wuxuu u baahan yahay inuu ogaado in cookie-ga aanu caddaynaynin intention-ka.

MUXUU Developer-ku u Illoobaa CSRF?

Developer-ku wuxuu u illoobaa CSRF sababtoo ah saddex waxyaabood:

1. Happy Path BiasDeveloper-ku wuxuu ku fikiraa user wanaagsan. Wuxuu yiraahdaa: "User-ku wuxuu buuxinayaa form-ka, wuxuu riixayaa Submit." Wuxuu illoobaa attacker-ka.

2. Framework TrustDeveloper-ku wuxuu aaminsan yahay framework-ka. Wuxuu yiraahdaa: "Framework-ku difaac ayuu leeyahay." Laakiin framework-ku wuxuu ilaalinayaa kaliya haddii si sax ah loo isticmaalo.

3. ComplexityCSRF waa mid adag. Waa mid qoto dheer. Developer-ku wuxuu rabaa shay fudud. Wuxuu illoobaa defense-in-depth.
