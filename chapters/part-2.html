HTTP Request: Anatomy

Aan bilowno request fudud. Markaad POST /login sameyso, HTTP request-ku wuxuu u eg yahay sidan:

Aan kala baxno qayb kasta. Qayb kastaa waxay leedahay macne

Request Line: POST /login HTTP/1.1

Qaybta 1: Method — POSTQaybta 2: Path — /loginQaybta 3: Version — HTTP/1.1

Method-ku wuxuu sheegaa ujeedda. Wuxuu yiraahdaa: "Waxaan rabaa inaan sameeyo wax." GET wuxuu yiraahdaa: "Waxaan rabaa inaan akhriyo." POST wuxuu yiraahdaa: "Waxaan rabaa inaan beddelo." PUT wuxuu yiraahdaa: "Waxaan rabaa inaan abuuro." DELETE wuxuu yiraahdaa: "Waxaan rabaa inaan tirtiro."

Method-ku waa state-changing mise safe? Haddii method-ku yahay GET oo uu beddelo state, waa khalad. Haddii method-ku yahay POST oo uu beddelo state, waa sax. Laakiin attacker-ku wuxuu isku dayaa inuu POST u beddelo GET sababtoo ah SameSite=Lax ma diro POST cross-site.

Marka aad aragto GET /change-email, is weydii: "muxuu server-ku u ogolaaday GET inuu beddelo state?" Tani waa red flag.

Host Header: Host: target.com

Host header-ku wuxuu sheegaa domain-ka la codsaday..

Host header-ku wuxuu ku xiran yahay SameSite. Marka browser-ku uu diro request, wuxuu eegaa Host header-ka si uu u garto in request-ku yahay same-site mise cross-site.

Cookie Header: Cookie: session=ABC123

Cookie header-ku wuxuu sheegaa badge-ka user-ka..

Referer Header: Referer: https://target.com/login

Referer header-ku wuxuu sheegaa bogga request-ku ka yimid. Waa context.

Referer waa defense oo jaban. Server-ku wuxuu xaqiijin karaa Referer, laakiin attacker-ku wuxuu tirtiri karaa (no-referrer) ama wuxuu khiyaanayn karaa (unsafe-url + history.pushState).

2.2.5 Origin Header: Origin: https://target.com

Origin header-ku wuxuu sheegaa origin-ka request-ku ka yimid. Waa scheme + host + port.

Origin waa defense awood leh haddii loo isticmaalo si sax ah. Laakiin server-ku.

Body: username=wiener&password=peter

Body-ga wuxuu sheegaa xogta la dirayo. Waa payload.

Body-ga wuxuu ku jiraa csrf token. Haddii token-ka maqan yahay, waa red flag. Haddii token-ka jiro laakiin aan la xaqiijin, waa red flag.

2.3 HTTP Response: Anatomy

Response-ku wuxuu u eg yahay sidan:

Status Code: 200 OK

Status code-ku wuxuu sheegaa natiijada. 200 waaOK. 302 waa redirect. 400 waa khalad. 403 waa diidmo.

Marka aad tijaabinayso CSRF, status code-ku wuxuu kuu sheegaa in request-ka la aqbalay. 200 waa success. 400 waa failure.

Set-Cookie: Set-Cookie: session=ABC123; SameSite=Strict

Set-Cookie header-ku wuxuu sheegaa cookie cusub. Waa aasaas CSRF defense.

Attributes:

  • SameSite=Strict|Lax|None — xaddida cross-site.
  • Secure — kaliya HTTPS.
  • HttpOnly — JavaScript ma akhriyi karo.
  • Domain — domain-ka cookie-ga.
  • Path — path-ka cookie-ga.
  • Expires/Max-Age — goorta uu dhamaado.

SameSite waa defense ugu muhiimsan. Haddii aan la dhigin, browser-ku wuxuu isticmaalaa default Lax (Chrome). Haddii SameSite=Strict yahay, CSRF waa mid adag. Haddii SameSite=None, CSRF waa mid fudud.

X-Frame-Options: X-Frame-Options: DENY

X-Frame-Options wuxuu sheegaa in bogga aan la geli karin iframe. Waa clickjacking defense.

.

Haddii X-Frame-Options maqan yahay, clickjacking waa possible. Clickjacking waa CSRF nooc kale — attacker wuxuu ku qasbaa victim inuu riixo button.2.4.2 SameSite: Falsafadda

SameSite waa defense ugu muhiimsan ee CSRF. Wuxuu leeyahay saddex qiime:

1. SameSite=Strict

Strict waa isolation. Wuxuu yiraahdaa: "Cookie-ga waa qarsoodi. Lama wadaago."

2. SameSite=Lax

3. SameSite=None

Top-Level Navigation vs Subresource

Top-level navigation waa marka browser-ku uu si toos ah ugu leexdo URL cusub:

  • <a href="https://..."> oo la riixo
  • <form action="https://..."> oo la submit-gareeyo

Subresource waa marka browser-ku uu soo raro resource:

: SameSite=Lax wuxuu dirayaa cookie-ga top-level navigation kaliya. SameSite=Strict ma diro waxba.

2.4.4 Default SameSite

Haddii server-ku aanu dhigin SameSite, browser-ku wuxuu isticmaalaa default:

  • Chrome: Lax
  • Firefox: Lax (recent versions)
  • Safari: Lax (recent versions)

Headers: Trust Boundaries

Headers waa trust boundaries. Waxaa jira headers oo browser-ku maamulo (ma beddeli karo attacker) iyo headers oo attacker-ku maamulo.

2.5.1 Browser-Controlled Headers

  • Host , Origin iyo Referer attacker-ku ma beddeli karo (laakiin wuu tirtiri karaa).

Attacker-Controlled Headers

  • User-Agent — attacker-ku wuu beddeli karaa.
  • Content-Type — attacker-ku wuu beddeli karaa (laakiin browser-ku wuu xaddidaa).
  • X-* — attacker-ku wuu beddeli karaa.

HTTP/2 iyo HTTP/3: Mustaqbalka

HTTP/2 iyo HTTP/3 waxay la yimaadeen isbeddello. Laakiin aasaaska CSRF wuu sii jiraa. Cookies wali waa la diraa. SameSite wali waa defense. Origin wali waa browser-controlled.

Protocol-ku wuu isbeddelaa. Laakiin falsafadda waa isla midii. Waa confused deputy. Waa statelessness. Waa trust boundary.
