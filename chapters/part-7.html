QAYBTA VII

QAYBTA VII SAMESITE, WEBSOCKET, IYO BEYOND

  • 26 qaybood
  • 13 tusaale
  • 1 jadwal

Waxaa jira dhibaato falsafadeed oo ku jirta web-ka. Dhibaatadu waa xuduudaha. Waa boundaries. Waa meesha wax kala go'aan.

Aan tusaale ku siiyo. Waa maxay "website"?

Jawaabta fudud: Waa example.com.

Jawaabta dheer : Waa example.com, www.example.com, cms.example.com, api.example.com, iyo example.co.uk Waa qaybo badan. Waa xuduudo aan caddayn.

Web-ku wuxuu leeyahay xuduudo aan la qeexin. Waa fuzzy boundaries. Waa overlapping boundaries. Waa nested boundaries.

Tani waa dhibaatada SameSite. SameSite wuxuu ku salaysan yahay "site". Laakiin "site" ma aha "origin". Waa mid ka weyn. Waa mid ka duwan.

Tani waa dhibaatada WebSocket. WebSocket wuxuu ku salaysan yahay "origin". Laakiin WebSocket handshake-ku ma leh CSRF token. Waa trust boundary oo jaban.

Tani waa dhibaatada sibling domain. Sibling domain waa isla site. Laakiin waa origin kala duwan. XSS on sibling domain wuxuu u ogolaataa attacker inuu same-site requests sameeyo.

Lab-yada sare waxay ku barayaan in xuduudaha aanay caddayn. Waa in aad barato sida loo arko xuduudaha. Waa in aad barato sida loo fahmo xuduudaha. Waa in aad barato sida loo jebiyo xuduudaha.

Site vs Origin

Fikradda Aasaasiga ah

Origin waa scheme + host + port. Tusaale:

  • https://example.com — origin.
  • https://cms.example.com — origin kale.
  • http://example.com — origin kale (scheme duwan).
  • https://example.com:8080 — origin kale (port duwan).

Site waa registrable domain (eTLD+1). Tusaale:

  • example.com — site.
  • cms.example.com — isla site.
  • www.example.com — isla site.
  • example.co.uk — site (eTLD waa co.uk).

Origin waa qayb. Site waa koox. Origin waa local. Site waa global. Labaduba waa trust boundaries laakiin heer kala duwan.

Origin waa aasaaska ee SOP (Same-Origin Policy). SOP wuxuu yiraahdaa:

"JavaScript-ka bogga A ma akhrin karo xogta bogga B haddii origin-yadu kala duwan yihiin."

Origin waa isolation. Waa quarantine. Waa sandbox. Wuxuu u sheegaa browser-ka: "Origin kastaa waa gobol. Ma gudbi karo."

Origin waa trust boundary oo adag. Laakiin ma ilaalinayso CSRF. CSRF wuxuu ku salaysan yahay cookies, ma aha origin. Cookies-ka waa la diraa site-ka, ma aha origin-ka.

Site

Site waa aasaas ee SameSite. SameSite wuxuu yiraahdaa:

"Cookie-ga lama diro cross-site. Waa in la diraa same-site."

Site waa koox. Waa family.. Wuxuu u sheegaa browser-ka: "Site kastaa waa qoys. Xubnaha qoyska waa la aqbalayaa."

:

  1. Sibling domains waa isla site.
  2. XSS on sibling domain wuxuu u ogolaataa attacker inuu same-site requests sameeyo.
  3. SameSite=Strict ma ilaalinayso sibling domain XSS.

Gap waa farqiqa u dhexeeya origin iyo site.

Tusaale:

  • https://cms.example.com iyo https://example.com waa origin kala duwan laakiin isla site.
  • SOP wuxuu yiraahdaa: "Kala duwan." SameSite wuxuu yiraahdaa: "Isku mid."

Lab-ka 7: Referer Validation Depends on Header Being Present

Lab-kan wuxuu leeyahay Referer validation oo ku xiran jiritaanka header-ka. Haddii Referer maqan yahay, server-ku wuu aqbalayaa.

Referer

Referer waa context. Waa direction. Waa halka. Waa waxa request-ku ka yimid.

Dhibaatada: Referer waa optional. Browser-ku wuu tirtiri karaa. Attacker-ku wuu tirtiri karaa. Marka, maqnaanshaha waa possible.

Lab-ka 8: Broken Referer Validation

Lab-kan wuxuu leeyahay Referer validation oo isticmaala substring match. Wuxuu aqbalayaa Referer: https://evil.com/?target.com.

Substring

Substring waa qayb. Waa fragment. Waa piece. Waa wax ka mid ah.

Substring wuxuu yiraahdaa: "Haddii target.com uu ku jiro Referer, waa sax." Laakiin target.com wuxuu ku jiri karaa meel kasta:

  • https://target.com/ — host.
  • https://evil.com/?target.com — query string.
  • https://evil.com/#target.com — fragment.
  • https://target.com.evil.com/ — subdomain.
  • https://evil.com/target.com — path.

Falsafadda Contains vs Equals

Contains waa inclusion. Equals waa identity.

  • Contains wuxuu yiraahdaa: "Waxaa jira qayb."
  • Equals wuxuu yiraahdaa: "Waa isla mid."

Contains waa weak. Equals waa strong. Marka aad xaqiijinayso identity, waa in la isticmaalaa Equals, ma aha Contains.

Tusaale:

Tallaabo 1: Login wiener

  • Eeg request-ka: Referer: https://target.com/my-account.

Tallaabo 2: Tijaabi Referer

  • Beddel Referer: https://evil.com → waa la diiday.

Tallaabo 3: Tijaabi substring

  • Beddel Referer: https://evil.com/?target.com → waa la aqbalay.
  • Gunaanad: Substring match.

Tallaabo 4: Samee exploit

Ogeysiis: Exploit server Head section-ka ku dar Referrer-Policy: unsafe-url.

Lab-ka 9: SameSite Lax via Method Override

Lab-kan wuxuu leeyahay SameSite=Lax. Cookie-ga lama diro cross-site POST, laakiin waa la diraa cross-site GET top-level navigation. Server-ku wuxuu ogolaadaa _method=POST.

Top-Level Navigation

Top-level navigation waa marka browser-ku uu si toos ah ugu leexdo URL cusub. Waa user-intended. Waa deliberate. Waa conscious.

Top-level navigation waa signal. Waa marker. Waa proof of intent. Marka user-ku uu booqdo bank.com, waa intentional. Marka <img> uu soo raro bank.com, waa incidental.

SameSite=Lax wuxuu aaminsan yahay top-level navigation. Wuxuu yiraahdaa: "Haddii uu top-level yahay, waa user-intended." Laakiin top-level navigation wuxuu noqon karaa attacker-controlled:

  • document.location = "https://..." — top-level.
  • <a href="https://..."> — top-level.
  • <form action="https://..."> — top-level.

Method Override

Method override Waa marka method-ka la beddelo. Waa marka POST noqdo GET ama GET noqdo POST.

Method override wuxuu yiraahdaa: "Haddii method-ku aanu shaqeyn, isku day mid kale."

Method override wuxuu u ogolaataa attacker inuu GET u beddelo POST. SameSite=Lax wuxuu aqbalayaa GET top-level. Marka, CSRF wuu shaqeeyaa.

Tusaale:

Server-ku wuxuu u arkaa POST. SameSite=Lax wuxuu u arkaa GET. Labaduba waa kala duwan. yihiin Waa gap.

Sida Loo Tijaabiyo

Tallaabo 1: Login wiener

Tallaabo 2: Tijaabi GET

  • Riix Send.
  • Haddii la aqbalo → waa shaqeynaysaa.

Tallaabo 3: Tijaabi method override

  • Ku dar _method=POST query string-ka.
  • Riix Send.
  • Haddii la aqbalo → waa vulnerable.

Lab-ka 10: SameSite Strict via Client-Side Redirect —

Lab-kan wuxuu leeyahay SameSite=Strict. Cookie-ga lama diro cross-site . Laakiin lab-kan wuxuu leeyahay client-side redirect gadget oo sameeya request labaad oo same-site ah.

Lab-kan wuxuu ku barayaa in SameSite=Strict aanu ilaalin haddii site-ku leeyahay gadget. Wuxuu ku barayaa in defense-in-depth aanu ku filnayn.

Gadget-ka

Gadget wuxuu u ogolaataa attacker inuu u gudbo defense-ka. Wuxuu u ogolaataa attacker inuu sameeyo request labaad.

Tusaale:

  • Request 1: Cross-site, top-level, GET → /post/comment/confirmation?postId=... (ma u baahna cookie).
  • Request 2: Same-site, top-level, GET → /my-account/change-email?email=... (cookie waa la diraa).

Request 1 waa bridge. Request 2 waa action. Labaduba waa same-site. SameSite=Strict wuxuu aqbalayaa same-site. Marka, CSRF wuu shaqeeyaa.

Client-Side Redirect

Client-side redirect Waa marka JavaScript uu sameeyo redirect. Waa marka browser-ku uu sameeyo request labaad.

Client-side redirect wuxuu u arkaa browser-ka in request-ka labaad uu yimid isla site-ka. Waa same-site. Cookie-ga waa la diraa.

Dhibaatada: Client-side redirect wuxuu u ogolaataa attacker inuu maamulo halka request-ku u socdo. Wuxuu u ogolaataa attacker inuu sameeyo request labaad.

Lab-ka 11: SameSite Strict via Sibling Domain (CSWSH)

Lab-kan wuxuu leeyahay SameSite=Strict. Laakiin wuxuu leeyahay sibling domain (cms-...) oo leh XSS. Attacker wuxuu u isticmaalaa XSS-ka si uu CSWSH uga sameeyo main domain-ka.

Lab-kan wuxuu ku barayaa in SameSite=Strict aanu ilaalin haddii sibling domain jiro. Wuxuu ku barayaa in "site" uu yahay mid ka weyn "origin".

Sibling domain waa domain oo wadaaga hal site. Tusaale:

Dhibaatada: Sibling domain wuxuu noqon karaa bridge. Haddii attacker uu XSS ku helo sibling domain-ka, wuxuu maamulaa browser-ka victim. Wuxuu sameeyaa request u socda main domain-ka. Waa same-site. Cookie-ga waa la diraa.

XSS on Sibling Domain

XSS waa code execution. XSS on sibling domain wuxuu u ogolaataa attacker inuu maamulo browser-ka victim gudaha site-ka. Wuxuu sameeyaa request kasta. Wuxuu akhriyaa response kasta.

Tusaale:

CSWSH

CSWSH waa Cross-Site WebSocket Hijacking. Waa CSRF nooca WebSocket.

CSWSH wuxuu u baahan yahay WebSocket handshake. Waa GET. Waa cookie-based. Ma leh CSRF token.

Dhibaatada: CSWSH wuxuu u baahan yahay same-site. Haddii attacker uu XSS ku helo sibling domain, wuxuu sameeyaa CSWSH. Waa same-site. Cookie-ga waa la diraa.

Lab-ka 12: SameSite Lax via Cookie Refresh

Lab-kan wuxuu leeyahay SameSite=Lax. Laakiin SameSite=Lax wuxuu leeyahay 2-minute window — haddii cookie la cusboonaysiiyo, wuxuu u dhaqmaa sida None.

Cookie Refresh

Cookie refresh waa falsafad. Waa marka cookie-ga la cusboonaysiiyo. Waa marka browser-ku uu helo Set-Cookie cusub.

SameSite=Lax wuxuu leeyahay window. Wuxuu yiraahdaa: "Haddii cookie-ga la cusboonaysiiyo, wuxuu u dhaqmaa sida None." Waa 2-minute window.

Dhibaatada: Attacker-ku wuxuu cusboonaysiin karaa cookie-ga. Wuxuu furi karaa window-ka. Wuxuu diraa POST.
